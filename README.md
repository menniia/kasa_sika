# Kasa Sika

**Your money. Your voice. Your control.**

*Kasa* means speak; *sika* means money. Kasa Sika lets people who cannot reliably use mobile-money
screens (blind and low-vision users, older people, people who do not read easily, people with motor
impairments) use MTN Mobile Money **by voice, in English or Twi**, without handing their phone or PIN to
anyone.

> **Kasa Sika authenticates the person. MTN authorizes the money.**
> Kasa Sika is not a wallet, a ledger or a payment network. It never holds money or balances.

Built for the 2026 MTN Ghana Tɛkyerɛma Pa Hackathon.

```
"Send 50 cedis to Ama."          →  "You are about to send 50 Ghana cedis to Ama Owusu, number ending 0 1 1 1.
                                      Say yes to continue, or no to cancel."
"Yes."                           →  "Please confirm it is you…"  (fingerprint or Kasa Sika passcode on the device)
                                 →  "Your transaction is being processed."
                                 →  "Your 50 Ghana cedis transfer to Ama Owusu was successful."
"Fa sidi aduonum kɔma Ama."      →  the same, in Twi, recognised and spoken by Khaya AI
```

## What is real, what is simulated

| | Status |
|---|---|
| Voice conversation, clarification, corrections, controls | **Implemented** |
| Twi recognition + Twi speech (Khaya AI ASR v3 / TTS v2) | **Implemented, verified live** |
| Transaction state machine, idempotency, reconciliation, audit (PostgreSQL) | **Implemented, tested** |
| Step-up authentication bound to each transfer (passcode; device biometrics) | **Implemented** (biometrics untested on a physical device) |
| Payments in the demo | **Mock provider** (no money exists), same pipeline as MTN |
| MTN Disbursements adapter (token, validation, transfer, status, callbacks) | **Implemented against the verified sandbox contract** |
| Debiting the user's own wallet; the user's balance | **REQUIRES_MTN_CONFIRMATION** (consent APIs) |
| Live money | **Disabled**: the API refuses to start with a non-sandbox MTN target |

Details: [MTN capability matrix](docs/integrations/mtn-capability-matrix.md).

## Quick start (fresh clone)

Prerequisites: .NET SDK 10, Node 20+, PostgreSQL 16+ (Docker **or** a local install).

```bash
# 1. Database (pick one)
docker compose up -d                        # Docker
pwsh scripts/dev-postgres.ps1               # no Docker: private cluster on 127.0.0.1:5433

# 2. Backend secrets (generated into dotnet user-secrets, outside the repo)
pwsh scripts/setup-secrets.ps1
dotnet user-secrets set "Khaya:SubscriptionKey" "<your Khaya primary key>" --project backend/src/KasaSika.Api
dotnet user-secrets set "Khaya:SecondarySubscriptionKey" "<your Khaya secondary key>" --project backend/src/KasaSika.Api

# 3. API (applies migrations and seeds the demo account on start)
dotnet run --project backend/src/KasaSika.Api          # http://localhost:5126

# 4. App
cd mobile && npm install
npx expo start          # press w for web, or scan the QR code with Expo Go on a phone on the same Wi-Fi
```

Demo account: **Continue with demo account** on the first screen. Its transfer passcode is **246810**
(mock payments only). The app finds the API automatically: `localhost` on web, the Expo host's LAN IP on a
phone. Override with `EXPO_PUBLIC_API_BASE_URL` in `mobile/.env`.

Smoke test without the app: `node scripts/smoke-conversation.mjs` (English) or
`node scripts/smoke-conversation.mjs http://localhost:5126 tw "Fa sidi aduonum kɔma Ama" "Aane"`.

Tests: `dotnet test backend/tests/KasaSika.UnitTests` (integration tests use the `kasa_sika_test`
database on 127.0.0.1:5433; override with `KASA_TEST_DB`).

On Windows, if `dotnet build` never returns in an automation shell, set
`MSBUILDDISABLENODEREUSE=1` and pass `-nodeReuse:false -p:UseSharedCompilation=false`.

## Configure secrets

Secrets **never** go in the repository, the mobile app, or `EXPO_PUBLIC_*` variables. The backend reads
them from `dotnet user-secrets` (development) or environment variables (`Section__Key`):

| Key | Purpose |
|---|---|
| `Security:JwtSigningKey`, `Security:FieldEncryptionKey`, `Security:FingerprintKey` | Generated by `scripts/setup-secrets.ps1` |
| `Khaya:SubscriptionKey`, `Khaya:SecondarySubscriptionKey` | Khaya AI (`Ocp-Apim-Subscription-Key`) |
| `Mtn:SubscriptionKey`, `Mtn:ApiUser`, `Mtn:ApiKey` | MTN Disbursements (sandbox). See [docs/integrations/mtn.md](docs/integrations/mtn.md) |
| `Payments:Provider` | `Mock` (default) or `MtnSandbox` |

The API refuses to start without the security keys, and refuses unsafe combinations (live MTN,
demo features with a non-test provider).
